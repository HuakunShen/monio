# Linux X11 active input grabbing

**Timestamp:** 2026-07-30 19:38 +08

## Core Decision/Topic

Replace the Linux/X11 `grab()` listen-only fallback with real, unprivileged
keyboard and pointer suppression suitable for CrossFlow source capture, while
leaving the existing XRecord/XTest provenance path unchanged.

## Options Considered

- Keep adapting `GrabHandler` to the XRecord listener and ignore its return
  value. Rejected because XRecord observes events but cannot prevent the local
  desktop from receiving them.
- Require the evdev/uinput backend for Linux grabbing. This can suppress at the
  kernel device layer and works independently of X11, but it requires broad
  `/dev/input` and `/dev/uinput` authority. Its selective re-injection path is
  also unreliable under Wayland/libinput.
- Use `XGrabKeyboard` and `XGrabPointer` under native X11, with XTest for
  compatible pass-through. Chosen because it provides real suppression for an
  ordinary desktop user without the `input` group or a privileged helper.
- Implement Wayland InputCapture/RemoteDesktop portals and libei immediately.
  This remains the preferred native Wayland direction, but requires a separate
  compositor-mediated backend and acceptance matrix.

## Final Decision & Rationale

The X11 backend now creates a dedicated off-screen `InputOnly` window and
actively grabs the keyboard and pointer. It acquires the keyboard first, then
the pointer, and rolls the keyboard grab back if pointer acquisition fails.
Known X11 grab statuses are returned as device-specific startup errors.

Returning `None` consumes the captured event. Passing keys and standalone
motion temporarily releases the relevant grab, replays the raw X11 event
through the process-scoped XTest injector, and reacquires the grab.

Pointer pass-through is necessarily gesture-level on X11. After a passed
button press is replayed, the receiving application owns an implicit pointer
grab until release. Monio yields that gesture and then reacquires the pointer;
the handler may not observe its intermediate motion or release. CrossFlow
should therefore consume and forward every source event while control is
remote instead of relying on selective local pass-through.

Active X11 grabs are exclusive but require neither root nor membership in the
`input` group. An earlier `AlreadyGrabbed` result on the native GNOME desktop
was traced to the GNOME screen shield while the session was locked. Unlocking
released the path and the test passed without a reboot.

## Key Changes Made

- Replaced the X11 listen adapter in `src/platform/linux/x11/listen.rs` with an
  active-grab event loop, explicit acquisition rollback, pass-through replay,
  pointer-gesture yielding, state synchronization, and stop/error cleanup.
- Added raw keycode, button-code, and absolute-motion replay helpers in
  `src/platform/linux/x11/simulate.rs`.
- Added `examples/x11_grab_detection.rs`, which independently checks consumed
  and passed keyboard/button/motion events, conflict reporting, partial-grab
  rollback, and cleanup after `Hook::stop()`.
- Made the diagnostic assert that keyboard focus and pointer routing reach its
  observer window. The observer was moved from `(32, 32)`, which sits under
  GNOME's top-bar/compositor overlay, to `(256, 256)` to avoid a false
  right-button pass-through failure.
- Updated public API documentation, README backend capabilities, example
  permission guidance, contributor instructions, and the cross-platform
  handoff.
- Applied the current strict Clippy simplifications in `examples/grab.rs` so
  all-target verification remains clean.

## Verification

- Native unlocked GNOME X11:
  `cargo run --features x11 --example x11_grab_detection` passed.
- Isolated X server:
  `xvfb-run -a cargo run --features x11 --example x11_grab_detection` passed.
- Both diagnostics observed consumed Q and left-button events only in the
  handler, passed W and the complete right-button gesture in the observer,
  consumed pointer motion only in the handler, expected conflict behavior,
  keyboard rollback after pointer acquisition failure, and released grabs
  after stop.
- `cargo test --all-features`: 15 unit tests and 12 doc tests passed; 3 doc
  tests were ignored.
- `cargo clippy --all-features --all-targets -- -D warnings`: passed.
- `cargo fmt --all -- --check`: passed.
- The existing native X11 provenance diagnostic still classified ControlLeft
  press/release and both pointer moves as
  `Injected { injector: ThisMonioSession }`.

# CrossFlow relative pointer capture lease

**Timestamp:** 2026-07-30 23:24 +08

## Core Decision/Topic

Align the macOS relative-pointer API with the existing CrossFlow-facing event
and injection surface, while adding an explicit lifecycle that can keep
physical mouse motion flowing after the local cursor reaches a display edge.

## Options Considered

- Make every macOS `grab()` automatically hide and disassociate the cursor.
  Rejected because generic event filtering must not unexpectedly take cursor
  ownership, and CrossFlow only needs that behavior while a route is remote.
- Add a second `grab_relative()` hook API. Rejected because event capture and
  cursor ownership have different lifetimes: CrossFlow may keep one hook alive
  while repeatedly changing between local and remote routes.
- Use `IOHIDManager` immediately for a device-level macOS path. Deferred
  because Core Graphics already exposes event deltas and cursor association,
  which is sufficient to unblock CrossFlow without expanding permissions and
  device-management scope.
- Use a process-wide RAII lease independent of Hook. Chosen because it models
  cursor ownership directly, gives normal Rust scope cleanup, and still allows
  Hook/channel shutdown to serve as an emergency restoration path.

## Final Decision & Rationale

`RelativePointerCapture` is a process-exclusive lease. On macOS it saves the
cursor point/display, hides the cursor, and calls
`CGAssociateMouseAndMouseCursorPosition(false)`. Release restores in a fixed
associate, warp, show order. Each successful restoration step is recorded, so
a retry after partial failure cannot repeat a successful warp or unbalance the
cursor visibility count.

The lease remains independent from `grab()`. CrossFlow can start one grab hook,
acquire the lease only when routing turns remote, release it when routing
returns local, and keep consuming the existing `MouseData::relative` shape.
All Hook and channel exit paths call the same global cleanup helper as a safety
net.

Linux exposes the same public lease as a no-op because XI2 RawMotion and evdev
`REL_X/REL_Y` already provide cursor-independent capture in their supported
grab paths. Windows acquisition explicitly returns `Error::NotSupported`;
adding Raw Input is intentionally separate from this API-alignment change.

## Key Changes Made

- Added the public `RelativePointerCapture` guard, exclusive-acquisition error,
  explicit release, active-state query, best-effort Drop, and hook cleanup
  result handling.
- Added the macOS Core Graphics backend with stale-state repair and
  step-aware restoration.
- Added Linux no-op and Windows unsupported platform contracts so the Rust API
  compiles consistently on all three operating systems.
- Connected blocking and background Hook exits plus sync/Tokio channel
  shutdown to emergency capture release.
- Added lifecycle, exclusivity, drop, hook-cleanup, and restoration-retry
  tests.
- Added a bounded `crossflow_relative_capture` diagnostic and documented the
  precise macOS, Windows, X11, and evdev behavior.

# Journal Entry - 2026-07-30

## Windows Synthetic Input Provenance

### Objective

Extend the macOS input provenance feature to Windows so callers can identify
events injected by the current Monio process session.

The supported claim is intentionally narrow:

- `Injected { injector: ThisMonioSession }` means the event was injected by
  this Monio process session.
- `Unknown` means Monio has no stronger retained evidence.
- `Unknown` is not proof that an event came from a physical device.

### Initial Investigation

The implementation started from commit `baa2bc7`, which already provided the
public `InputOrigin` API and macOS session tagging.

An older diagnostic run on Windows produced:

- Simulated Control press/release: observed
- Simulated mouse target/restoration: not matched

A second unfiltered listener proved that Windows did receive both simulated
mouse events. The reported hook coordinates were approximately 1.5 times the
requested coordinates because the machine used 150% DPI scaling:

```text
Requested: (1475, 814), (1443, 790)
Hook:      (2213, 1222), (2165, 1186)
```

Therefore, the mouse events were not missing. The old diagnostic compared
coordinates from different Windows DPI coordinate spaces.

The investigation also confirmed that Windows low-level hooks receive Monio
`SendInput` events for both keyboard and mouse. Windows does not automatically
exclude simulated input, so explicit provenance handling is required.

### Provenance Design

Windows provides two complementary signals:

1. `LLKHF_INJECTED` for keyboard events and `LLMHF_INJECTED` for mouse events
   indicate that Windows considers the event injected.
2. `dwExtraInfo` carries a Monio process-session tag.

Monio classifies an event as `ThisMonioSession` only when:

- the applicable Windows injected flag is set;
- the observed tag is nonzero; and
- `dwExtraInfo` exactly matches the current process-session tag.

Checking only the injected flag would not distinguish Monio from other
software. Checking only the tag would omit the operating system's injection
evidence.

### 32-bit Mouse Tag Discovery

The first implementation used a random `usize` tag. Keyboard events preserved
the full value, but the Windows mouse hook retained only the low 32 bits:

```text
Expected tag: 0x16c7368f0fd87868
Mouse hook:   0x000000000fd87868
Flags:        0x1 (LLMHF_INJECTED)
```

The Windows session tag was therefore changed to a random, nonzero `u32`
stored as `usize`. The same tag now round-trips through keyboard and mouse
hooks.

### TDD Coverage

Tests were written and observed failing before each production behavior was
implemented:

- Only an injected event with the exact nonzero tag is classified as the
  current Monio session.
- The process-session tag is stable and nonzero.
- The Windows tag fits the 32-bit mouse `dwExtraInfo` round-trip.
- Converted keyboard and mouse hook events preserve
  `ThisMonioSession`.
- Constructed keyboard and mouse `SendInput` records carry the session tag.
- The native diagnostic recognizes tagged mouse events across different DPI
  coordinate spaces.
